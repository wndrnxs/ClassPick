## 1. 기능 설정 구조 — 학원·선생님별로 기능 켜고 끄기 (보류 · 2026-10-17)

**배경**: 학원마다 원하는 기능이 다릅니다. 예) 문항 질문 기능이 선생님 업무에 부담이 되어 끄고 싶은 학원.

**검토한 선택지**

| 방식 | 장점 | 한계 |
|---|---|---|
| 관리자(학원장) 페이지만 | 학원 전체 정책 통일 | 혼자 쓰는 선생님은 관리자가 없음, 반마다 다르게 못 함 |
| 선생님 설정만 | 바로 만들 수 있고 단순 | 원장이 학원 전체를 통제할 수 없음 |
| 기능 옵션화 | 켜고 끄는 것이 데이터라 어느 화면에서든 사용 | 그 자체로는 "누가 바꾸는가"가 정해지지 않음 |

**권장안**: 기능을 옵션(설정값)으로 만들고, 그 옵션을 정하는 단계를 나눕니다.

```
학원 정책 (원장)     "질문 기능: 끔" + 잠금  ← 잠그면 아래 단계에서 못 바꿈
  └ 선생님 기본값    "질문 받기: 켬"
      └ 반·시험별    "이 시험은 질문 안 받음" (배포 창에서 선택)
```

- 적용 규칙: 잠긴 항목은 원장 값, 잠기지 않은 항목은 가장 구체적인 설정(시험 > 반 > 선생님 > 학원).
- 혼자 쓰는 선생님은 선생님 설정 화면이 곧 관리 화면.
- 원칙: 꺼진 기능은 화면만 숨기지 말고 **API에서도 거부**. 기능을 꺼도 **기존 질문·답변은 읽기 전용으로 보존**.

**질문 기능의 업무 부담을 줄이는 중간 옵션 후보**: 질문 받는 기간(마감 후 N일), 학생당 질문 수 제한, 조교·다른 선생님이 대신 답변, AI 답변 초안(선생님 확인 후 전송), 공개 Q&A 우선 노출(구현됨).

**단계안**
1. 설정 구조 + 선생님 설정 화면 + 배포 창의 「질문 받기」 옵션
2. (학원 요금제 출시 시) 학원 테이블, 원장·선생님·조교 역할, 「학원 관리」 화면(선생님 초대, 기능 잠금)

**결정할 것**: 1단계 진행 시점 · 질문 기능의 기본값(켬/끔) · 중간 옵션 중 무엇을 넣을지 · 학원 요금제 출시 시점

**관련 코드**: `src/server/services/inquiries.ts`, `src/components/classroom/distribute-dialog.tsx`, `src/server/db/schema.ts` (`users.organization`은 현재 글자 칸뿐, `plan`에 `academy` 값만 있음)

## 2. 역대 수능 기출 조회·출력 (보류 · 방식 선택 필요)

- 기출 원문을 그대로 보여 주거나 출력하게 하면 저작권 위험이 큽니다. 평가원 허락이 필요하고, 현대 문학 지문은 작가 쪽 허락도 필요합니다(저작권법 제32조의 영리 목적 예외, 2024년 대법원 판결 등).
- 권장: **① 기출 색인·분석 DB**(연도·번호·작품·유형 등 정보와 자체 분석만 저장, 원문은 평가원 링크) + **② 기출 유형 기반 새 문항 생성**. 원문 제공은 **④ 정식 라이선스**(평가원 + 한국문학예술저작권협회)를 받은 뒤에.
- 결정할 것: 진행 여부 · 기출 정보 데이터를 누가 어떻게 검수할지 · 정식 출시 전 법률 확인

## 3. 다음 기능 후보

우선 추천 순서
1. 문항 변별도·품질 분석 (상위/하위 27% 정답률 차, 정답 시비 가능 문항 경고) — 작업량 적음
2. 오답 재도전(간격 반복) + 쌍둥이 문항 자동 생성
3. 서술형 AI 채점 보조 (채점 기준으로 초안 점수 → 선생님 확인)

지문 서식·옛한글 후속 (2026-10-19 기본 기능 구현 후 남은 것)
- HWPX·DOCX **파일 업로드** 시에도 굵게·밑줄·박스 가져오기 (지금은 붙여넣기만 서식 유지)
- 예전 HWP 문서의 **한컴 전용 옛한글 코드(한양 PUA) → 유니코드 변환**: 변환표가 필요함. 공개 구현(hypua2jamo)은 LGPL이라 그대로 넣기 전에 라이선스 검토 필요. 지금은 편집기에서 경고만 표시
- 한컴오피스에서 서식(밑줄·글자 테두리)과 옛한글이 든 HWPX를 실제로 열어 보기 (자동 검증만 통과)
- 2단 HWPX(제목 1단 → 본문 2단 다단 설정)를 한컴오피스에서 실제로 열어 단 나눔·구분선 확인 (OWPML 스키마 검증·DOCX 변환 확인만 함)
- 자료 수정 이력(되돌리기)·AI로 한 문항만 다시 만들기: 지금은 저장하면 덮어씀

그 밖에: 학생 개인 성적표(PDF·HWPX), 문제 은행(실제 정답률·풀이 시간 포함), 실전 모의고사 모드(OMR), 시간 전략 코칭, 마감 일시 예약·자동 마감, 선지 순서 섞기·탭 이탈 기록, 배포·마감 알림

## 4. 실제 학생에게 열기 전 필수 점검

- **영구 DB**: Render 무료 플랜은 재배포 시 SQLite 데이터가 지워짐 → **코드 준비 완료**: `DATABASE_URL`·`DATABASE_AUTH_TOKEN`을 넣으면 Turso 등 호스팅 libSQL 사용 (실제 Turso 연결 확인은 아직 안 함). 또는 Render 유료 플랜 + Persistent Disk에 `DATABASE_PATH` 지정
- **만 14세 미만 가입**: 개인정보보호법상 법정대리인 동의 필요 → 생년 확인·보호자 동의 절차, 또는 선생님이 학생 계정을 발급하는 방식
- **이용약관·개인정보처리방침 법률 검토**, 결제위젯 연동 (README 「다음 단계 제안」 참고)
- **경쟁사 특허 침해 검토(FTO)**: 「문제G」(대교 계열 디피니션)가 2025-11-04 핵심 기술 특허 등록을 발표함(상표 41·42·09류 별도). 특허는 아이디어가 아니라 청구항의 구체적 방법만 보호하므로 청구항 확인이 먼저
  - KIPRIS에서 출원인 「디피니션」/「대교」, 키워드 「문제 생성」·「지문」으로 특허 번호·청구항 확인
  - 독립항의 구성 요소를 클래스픽 구현과 하나씩 대조 (문제G는 「유사 지문 생성」 중심, 클래스픽은 입력 지문 그대로 문항·해설 생성 — 추정이므로 확인 필요)
  - 겹치면 회피 설계 / 선행 기술로 무효 주장 / 라이선스 중 선택
  - 비영리 테스트는 위험 낮음(특허법 제94조 「업으로서」), **유료 출시 전 변리사 FTO 분석 권장**
- **샘플 문항 검수**: 「진달래꽃」 5지선다 2번 ③ 선지는 '역설적으로 강조한다'인데 해설은 '반어법'으로 설명함 → 용어 통일 필요 (`src/lib/samples/azalea.ts`)
